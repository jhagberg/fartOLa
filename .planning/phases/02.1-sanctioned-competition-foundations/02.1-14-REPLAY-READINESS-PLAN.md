# Replay readiness — fix list before replaying a real competition

> **For agentic workers:** implement task by task, in order. Each task: write the
> failing test first, run it and see it fail, implement, run the full gate,
> commit (one task = one commit). Tasks depend on earlier ones only through the
> interfaces named in each task.

**Goal:** fartOLa computes the same status and running time as MeOS/Eventor for
a real 634-runner competition day replayed through its normal import and
card-read paths.

**Architecture:** Fixes land in `apps/edge` on branch `phase-2.1-merge`. Start
times become one base (epoch ms), status detection follows the orienteering
rule (course controls in order, extras allowed), classes point at courses, and
a replay script drives a real server instance (imports via HTTP, card reads via
`insertEvent`) and diffs the projection against the official result.

**Tech stack:** Node 24, TypeScript (strict, `exactOptionalPropertyTypes`),
Fastify, Drizzle + better-sqlite3, `node:test`. Svelte web app only where a
display depends on the start-time base.

**Spec:** the gap audit `02.1-AUDIT-2026-10-04.md` (section "Top gaps") and the replay fixture format in
`jhagberg/fartOLa-tools` → `replay/README.md` (CourseData.xml, EntryList.xml,
StartList.xml, readouts.ndjson with `card_read` events and `ts_ms`,
expected.json with `{runner, card, className, status, start, finish, time,
position, splits}` per runner).

## Review focus

1. Runs that cross 12:00 — elapsed must not be ~12 h.
2. A runner with a drawn start time who also punched a start unit late — drawn time wins (MeOS default); open-start classes (no drawn time) use the punch.
3. Two classes sharing one course (dag 1: 44 classes on 23 courses) — both get the course.
4. Butterfly/repeated controls and stray double punches — not MP.
5. SI5 cards (no PM bit) read in the afternoon — times placed in the 12 h before the read.

### Task 2: Status = course controls in order as a subsequence

**Files:** `apps/edge/src/projection/dnfMp.ts`, `dnfMp.test.ts`.

**Rule:** walk the expected codes; for each, find it in the punches after the previous match (greedy). Missing = expected codes not found. OK iff nothing missing (and finish present — DNF gate unchanged). `extra_codes` = punches not used in the match (informational, never cause MP). `out_of_order_codes` = expected codes that exist in the punches but only before the previous match (informational; they are also in `missing_codes`). This is the algorithm that matched MeOS on 633/633 runners of DM dag 1.

**Tests:** extras anywhere → OK; double punch at a control → OK; butterfly course `[31,32,31,33]` with punches `31,32,31,33` → OK and with `31,32,33` → MP missing `[31]`; wrong order: expected `[31,32]`, punches `32,31` → MP, missing `[32]`, out_of_order `[32]`, extra `[32]`; old test 4 rewritten: extra punch → OK, `extra_codes` lists it.

### Task 3: Card clock → absolute time (PM bit, SI5 inference, elapsed from drawn start)

### Task 8: Replay script

**Files:** create `apps/edge/scripts/replay.ts` and `apps/edge/scripts/replay.test.ts` (the test runs the script against a 3-runner fixture written in the test; the real fixture is used only when `FARTOLA_REPLAY_DIR` is set).

**Flow:** `buildServer({ dbHandle: tmp in-memory db })` → create competition (name/date from `manifest.json`) → POST CourseData, EntryList, StartList through the import routes with `app.inject` + `FormData` (see `routes/import.test.ts:71-90`) → insert `race_started` at the first read's time → for each line of `readouts.ndjson`, `insertEvent(handle, nodeId, 'card_read', line.ts_ms, payload, competitionId)` → load + reduce via the same loader the server uses → compare with `expected.json`.

**Comparison:** per runner (by card number): status mapping `OK↔OK`, `MissingPunch↔MP`, `DidNotFinish↔DNF`, `DidNotStart↔PEND|DNS`; time within 1 s when both OK. Print a table of mismatches grouped by class and a summary line `N/634 equal`. Exit 0 always (it is a report); the test asserts the 3-runner fixture is 3/3.

**Run:** `FARTOLA_REPLAY_DIR=… pnpm --filter @fartola/edge exec tsx scripts/replay.ts`.

### Task 9: Classes without timing (MeOS NoTiming, IOF `resultListMode="UnorderedNoTimes"`)

Added after the first dag-1 replay (633/634): Inskolning is untimed in MeOS
(`oClass.NoTiming=1`) and Eventor's ResultList marks it with
`<Class resultListMode="UnorderedNoTimes">` and gives no Time, FinishTime or
Position. fartOLa has no such concept and shows times and places.

**Behaviour (as MeOS, `iof30interface.cpp` ~3049 import, ~3573 export):**
- `classes.no_timing` boolean (migration, default false), shown in the class DTO.
- Import: CourseData/EntryList `<Class resultListMode="UnorderedNoTimes">` → `no_timing = true`.
- Status detection unchanged (OK/MP/DNF still computed). For runners in a no-timing class the projection keeps `elapsed_time_ms` internally but result views get `place: null`, `behind_leader_ms: null`, and the class's results sort by name; anything shown to the public (results route, WS results channel, liveresultat MOP, receipts) shows no time.
- IOF ResultList export: the class gets `resultListMode="UnorderedNoTimes"` and its runners get no `Time`, `TimeBehind`, `Position` (keep `StartTime`, `Status`, `SplitTime` codes without times is fine — mirror Eventor: SplitTime with ControlCode only).
- Class PATCH accepts `no_timing`; the web class editor gets a "Utan tidtagning" toggle.

**Tests:** import sets the flag; reducer/result view: two OK runners in a no-timing class → both `place: null`, sorted by name, no behind; ResultList export has the attribute and no Time/Position for that class but has them for a normal class; PATCH toggles it.

### Task 10: Operator can set MP by hand

MeOS lets the secretariat set "Felstämplad" by hand, e.g. for a runner who
went home without reading out (DM dag 1, Vit 2,0). fartOLa's manual statuses
are DNF/DNS/DQ/CANCEL/MAX only.

- `ManualStatus` gains `'MP'` (`projection/types.ts:38`), the manual-status route and its zod schema accept it, the reducer applies it like the other manual statuses (wins over auto-detect, clearing reverts to auto), and the web manual-status picker offers "Felstämplad".
- **Tests:** set MP on a runner without a read-out → MP; set MP on an OK read-out → MP; clear → back to auto status; MP set by hand is not promoted to MAX.
