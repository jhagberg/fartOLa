# Replay readiness — fix list before replaying a real competition

> **For agentic workers:** implement task by task, in order. Each task: write the
> failing test first, run it and see it fail, implement, run the full gate,
> commit (one task = one commit). Tasks depend on earlier ones only through the
> interfaces named in each task.

**Goal:** fartOLa computes the same status and running time as MeOS/Eventor for
a real 634-runner competition day replayed through its normal import and
card-read paths.

**Architecture:** Fixes land in `apps/edge` on branch `phase-2.1-merge`. Start
times become one base (epoch ms), status detection follows the orienteering
rule (course controls in order, extras allowed), classes point at courses, and
a replay script drives a real server instance (imports via HTTP, card reads via
`insertEvent`) and diffs the projection against the official result.

**Tech stack:** Node 24, TypeScript (strict, `exactOptionalPropertyTypes`),
Fastify, Drizzle + better-sqlite3, `node:test`. Svelte web app only where a
display depends on the start-time base.

**Spec:** the gap audit `02.1-AUDIT-2026-10-04.md` (section "Top gaps") and the replay fixture format in
`jhagberg/fartOLa-tools` → `replay/README.md` (CourseData.xml, EntryList.xml,
StartList.xml, readouts.ndjson with `card_read` events and `ts_ms`,
expected.json with `{runner, card, className, status, start, finish, time,
position, splits}` per runner).

## Review focus

1. Runs that cross 12:00 — elapsed must not be ~12 h.
2. A runner with a drawn start time who also punched a start unit late — drawn time wins (MeOS default); open-start classes (no drawn time) use the punch.
3. Two classes sharing one course (dag 1: 44 classes on 23 courses) — both get the course.
4. Butterfly/repeated controls and stray double punches — not MP.
5. SI5 cards (no PM bit) read in the afternoon — times placed in the 12 h before the read.

### Task 2: Status = course controls in order as a subsequence

**Files:** `apps/edge/src/projection/dnfMp.ts`, `dnfMp.test.ts`.

**Rule:** walk the expected codes; for each, find it in the punches after the previous match (greedy). Missing = expected codes not found. OK iff nothing missing (and finish present — DNF gate unchanged). `extra_codes` = punches not used in the match (informational, never cause MP). `out_of_order_codes` = expected codes that exist in the punches but only before the previous match (informational; they are also in `missing_codes`). This is the algorithm that matched MeOS on 633/633 runners of DM dag 1.

**Tests:** extras anywhere → OK; double punch at a control → OK; butterfly course `[31,32,31,33]` with punches `31,32,31,33` → OK and with `31,32,33` → MP missing `[31]`; wrong order: expected `[31,32]`, punches `32,31` → MP, missing `[32]`, out_of_order `[32]`, extra `[32]`; old test 4 rewritten: extra punch → OK, `extra_codes` lists it.

### Task 9: Classes without timing (MeOS NoTiming, IOF `resultListMode="UnorderedNoTimes"`)

Added after the first dag-1 replay (633/634): Inskolning is untimed in MeOS
(`oClass.NoTiming=1`) and Eventor's ResultList marks it with
`<Class resultListMode="UnorderedNoTimes">` and gives no Time, FinishTime or
Position. fartOLa has no such concept and shows times and places.

**Behaviour (as MeOS, `iof30interface.cpp` ~3049 import, ~3573 export):**
- `classes.no_timing` boolean (migration, default false), shown in the class DTO.
- Import: CourseData/EntryList `<Class resultListMode="UnorderedNoTimes">` → `no_timing = true`.
- Status detection unchanged (OK/MP/DNF still computed). For runners in a no-timing class the projection keeps `elapsed_time_ms` internally but result views get `place: null`, `behind_leader_ms: null`, and the class's results sort by name; anything shown to the public (results route, WS results channel, liveresultat MOP, receipts) shows no time.
- IOF ResultList export: the class gets `resultListMode="UnorderedNoTimes"` and its runners get no `Time`, `TimeBehind`, `Position` (keep `StartTime`, `Status`, `SplitTime` codes without times is fine — mirror Eventor: SplitTime with ControlCode only).
- Class PATCH accepts `no_timing`; the web class editor gets a "Utan tidtagning" toggle.

**Tests:** import sets the flag; reducer/result view: two OK runners in a no-timing class → both `place: null`, sorted by name, no behind; ResultList export has the attribute and no Time/Position for that class but has them for a normal class; PATCH toggles it.

### Correction to Task 3 (verified in MeOS source, 5.0 Update 3)

Task 3 said "drawn time wins (MeOS default)". That is wrong. In MeOS the
card's start punch **always** replaces the start time when it differs
(`oRunner.cpp:1331-1344`, plain `!=`, no tolerance), unless the class has
IgnoreStart ("Ej startstämpling") **and** the runner has a start time
(`oRunner.cpp:1226-1227`). Seen on DM dag 1: D10 runner moved to 10:22:00,
punched start 10:22:06, official time from 10:22:06.

### Task 11: Start punch wins over the start time unless the class ignores start punches

- `detectStatus`/`elapsedMs`: start = card start punch if present, else drawn
  start; when the class has `ignore_start_punch` and the runner has a drawn
  start, use the drawn start.
- `classes.ignore_start_punch` boolean (migration, default false), class DTO
  `ignore_start_punch`, class PATCH, web toggle "Ej startstämpling" next to
  "Utan tidtagning".
- Same rule wherever a running time is computed (reduce.ts voided-leg pass,
  web `readElapsedMs`).
- **Tests:** drawn 10:22:00 + punch 10:22:06 → from 10:22:06; same with
  ignore_start_punch → from 10:22:00; ignore_start_punch but no drawn start →
  punch; no punch → drawn.

### Task 12: A later read-out re-scores every manual status except DQ

MeOS `evaluateCard` (`oRunner.cpp:1621-1630`): a stored DNS, CANCEL, MP or DNF
becomes OK with an OK card; MAX becomes OK only within max time; DQ stays.
cab15d8 did this for DNS/CANCEL only. Extend to MP, DNF and MAX: a
card_read after any manual status other than DQ clears it and the card is
scored (MAX is then re-derived from the class max time). A manual status set
**after** the read still wins (fartOLa keeps the operator's later decision;
MeOS would show OK and warn "Status matchar inte data i löparbrickan").
- **Tests:** DNF by hand → OK read → OK; MP by hand (no read yet) → OK read →
  OK; DQ → read → DQ; MAX by hand → read within max → OK, over max → MAX.

### Task 13: Warn at read-out when there is no start, and suggest one

MeOS gives no warning and silently times from ZeroTime (`oRunner.cpp:819-826`;
Tuna Ting dag 2, Vit 2,0: 1:53:05 for a ~33 min run). fartOLa:
- Projection: a competitor whose latest read has a finish but neither a start
  punch nor a drawn start gets `missing_start: true`, no elapsed time, no
  place, status as detected (OK/MP).
- Suggestion `suggested_start_ms`: the card's check punch + the median
  (check → start punch) of the competition's runners with both, read so far;
  fallback 1:54 when fewer than 10 such runners (median of DM 2026 dag 1–2,
  424 open starts, `02.1-AUDIT`). Null when there is no check punch.
- Web read-out card: a warning "Saknar starttid" with the suggestion shown
  as check time + median ("Check 10:19:37 + 1:54 → 10:21:31"), an editable
  time field prefilled with it, and "Sätt starttid" which calls the existing
  PATCH start-time route. Also listed in a "Saknar starttid" filter/count on
  the runners list if one exists.
- **Tests:** projection flag + suggestion with ≥10 and <10 reference runners
  and without check punch; web component renders the warning and calls the
  route with the edited value.

### Decision 2026-10-05: follow SOFT, not MeOS, for the start

SOFT Regelverk för orientering, version 20260701_2 (in force 2026-07-01;
renumbered from the 2022-07-01 edition, same start rules): TR 4.18.9
"Tävlande som av egen orsak kommer för sent till start ska ha möjlighet att
starta snarast, men ursprunglig starttid gäller" (new start time only for
the organiser's mistake; was 5.5.2); TA "Sen start" right after it; TR
4.18.16 start punching is an allowed start method, all with the same start
time must be able to punch within 10 s of the start signal, and "Funktionär
ska övervaka att inte den tävlande medvetet väntar in annan tävlande" (was
5.5.8); TR 8.2.8 start punching "snarast efter startsignalen", tjuvstart
forbidden (was 6.2.7; TR 4.18.14 gives +1 min only where start punching is
not used — fartOLa only warns); TR 7.4.2 / 7.4.3 fri starttid only in open
classes (was 5.2.2). So in a class with start times the start punch must
not move the start. MeOS's default (punch wins, Task 11) contradicts this; fartOLa
follows SOFT and reports the MeOS difference in the replay. Code, tests and
commits cite "SOFT TR x (2026-07-01)".

### Task 14: Start method per class, SOFT rule by default

- Replace `classes.ignore_start_punch` (Task 11, unreleased) with
  `classes.start_method`: `'auto' | 'start_time' | 'start_punch'`, default
  `'auto'`. Migration converts ignore_start_punch=true → 'start_time', false →
  'auto'.
  - `start_time`: time from the runner's start time (drawn, or set by the
    secretariat, e.g. organiser's mistake per TR 4.18.9). Start punch ignored.
  - `start_punch`: time from the start punch (MeOS behaviour; SOFT TR 4.18.16
    "startstämpling" as start method). No punch → drawn start, else missing.
  - `auto`: `start_time` when the runner has a start time, else `start_punch`
    (open classes / fri starttid have no start times).
- Warning, not a time change: in `start_time` classes, a start punch more
  than 60 s after the start time → `late_start_ms` on the view ("Sen start
  +3:12"); a start punch before the start time → `early_start_ms`
  ("Tjuvstart?"). Shown on the read-out card for the jury.
- UI: replace the "Ej startstämpling" checkbox with "Starttid räknas från:
  Automatiskt / Starttid / Startstämpling".
- Replay: classify the D10 runner (moved 10:22:00, punch 10:22:06) as an
  intended difference — the replay report gets a "Skillnad mot MeOS (SOFT
  TR 4.18.9)" section instead of counting it as a mismatch. Keep it testable:
  `--meos-start` option that runs with `start_punch` everywhere and must give
  634/634 on dag 1.
- **Tests:** the three methods × {drawn start, punch, both, neither}; late /
  early warnings with exact thresholds; migration mapping; class PATCH.

### Task 15: "Fastställ saknade starttider" before results are fixed

At read-out a runner without start gets the warning and no time (Task 13).
When the race is over the secretariat sets them all at once with the
day's final numbers:
- Route `GET /api/competitions/:id/missing-starts`: every competitor with
  `missing_start`, with check time, suggested start (check + median of the
  day's check→start gaps among runners with both, all reads; fallback 1:54
  below 10), the median and the mean, and n.
- Route `POST /api/competitions/:id/missing-starts/apply`
  `{ items: [{ competitor_id, start_time_ms }] }` sets each start time (same
  validation as the PATCH start-time route), in one transaction.
- Web: a "Saknade starttider" panel (results/secretariat view): table with
  name, class, check, suggested start (editable), resulting time; header shows
  "median 1:54 (medel 2:07, n=213)"; "Sätt alla" and per-row "Sätt".
- **Tests:** listing with suggestions; apply sets times and the runners get
  times and places; validation errors roll back the whole batch.
