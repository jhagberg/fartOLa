# 02.1-15: one start choice per class (ADR-0018)

> **For agentic workers:** REQUIRED SUB-SKILL: use
> superpowers:subagent-driven-development (or executing-plans) to run this
> plan task by task. Steps use checkboxes.

**Goal:** the operator says once how a class starts, with three answers, and
Lottning, Kontroll and the results all read that answer.

**Decision:** `docs/decisions/0018-one-start-choice-per-class.md`. Read it
first; it has the table and the rules every task implements.

**Rules:** ADR-0011 (SOFT TR 4.18.16, 7.4.2, 7.4.3), ADR-0016 (show before,
say after; rule 7 floors: 14 px, 44 px, never colour alone; plain Swedish),
ADR-0014 (replay), ADR-0003.

**Tech:** Fastify edge with Drizzle/SQLite and the event-sourced projection;
Svelte 5 web; node:test (edge), vitest (web), Playwright.

## Global constraints

- One column, one new value: `classes.start_method` gains `free_start`.
  The column is plain TEXT (migration 0014), so **no migration**: nothing
  stored is rewritten.
- Stored `auto` keeps its meaning (the runner's start time, else the start
  punch). `free_start` times exactly like `start_punch` (punch, else drawn
  time).
- A class that keeps its stored value scores the same as before: time,
  status, place, `missing_start`, late and early start warnings.
- Never raw server text or codes in the UI; new keys in `sv.json` and
  `en.json`.
- Gate per task: `rtk proxy pnpm lint && pnpm typecheck && rtk proxy pnpm test`.
  e2e behind `flock /tmp/fartola-e2e.lock pnpm exec playwright test <specs> --workers=2`.
- Tests: a test for **changed** behaviour is shown RED first, with the
  reason it fails on the old code. A **compatibility** test (unchanged
  `auto`, `start_time`) is expected green on the old code; say which is
  which in the report. Edge tests are transpiled, not type-checked, so a
  missing enum value does not make them fail by itself.
- Commits: Conventional Commits, one per task, no trailers.

## The table (from the ADR)

| Answer (sv)                        | Stored        | `startSource`     | `classNeedsStartTimes` |
| ---------------------------------- | ------------- | ----------------- | ---------------------- |
| Lottad starttid                    | `start_time`  | drawn             | true                   |
| Lottad starttid och startstämpling | `start_punch` | punch, else drawn | true (was false)       |
| Fri start med startstämpling       | `free_start`  | punch, else drawn | false                  |
| not chosen (older competitions)    | `auto`        | drawn, else punch | unchanged legacy rule  |

Two rule predicates, both only for a **confirmed** kind at nivå 1–3:

- `freeStartForbidden`: an age class (TR 7.4.2). Exists. Forces
  `classNeedsStartTimes` to true, whatever is stored.
- `freeStartRequired` (new, next to it): an open class or inskolning
  (TR 7.4.3, 3.4.9). Forces `classNeedsStartTimes` to false, whatever is
  stored.

At nivå 4, träning or no level, neither holds: any class may take any
answer.

### Task 2: Kontroll's rule, the guards and the defaults (edge)

**Files:** `apps/edge/src/projection/preRaceCheck.ts`,
`apps/edge/src/routes/preRaceCheck.test.ts`,
`apps/edge/src/routes/classes.ts` + `classes.test.ts`,

`apps/edge/src/draw/classKind.ts`, `apps/web/src/lib/api/client.ts` (the

- [ ] **Step 1, `classNeedsStartTimes`:**

  ```ts
  if (freeStartForbidden(cls, level)) return true;
  if (freeStartRequired(cls, level)) return false;
  if (cls.startMethod === 'free_start') return false;
  if (cls.startMethod === 'start_time' || cls.startMethod === 'start_punch') return true;
  return cls.firstStartMs !== null || anyRunnerHasStartTime; // auto, older competitions
  ```

  Tests. RED: `start_punch` in a class where free start is not forbidden
  and nothing is drawn → true; `free_start` when one runner has a start
  time → false (old code: `auto`-like fallthrough gives true).
  Compatibility: `auto` (false with nothing drawn; true with
  `firstStartMs` or one runner with a time), `start_time`, and
  `free_start` in a confirmed age class at nivå 2 → true. New:
  `start_time` in a confirmed open class at nivå 2 → false (the conflict
  row reports it instead), and → true at nivå 4.

- [ ] **Step 2, the conflict row:** the check payload gains
      `start_choice_conflicts: Array<{ class_id; class_name; runners;
      reason: 'free_start_forbidden' | 'free_start_required' }>`: every
      class stored as `free_start` for which `freeStartForbidden` holds,
      and every class stored as `start_time` or `start_punch` for which
      `freeStartRequired` holds, **whether or not its runners have start
      times** (a class where all runners have a time is otherwise
      silent). A class stored as `auto` is never a conflict. Each
      `no_start_time` row gains `free_start_banned: boolean`. Update the
      web `PreRaceCheck` type and its fixtures. Tests: free start stored,
      then the kind confirmed as an age class at nivå 2 → the class is in
      `start_choice_conflicts` also when every runner has a start time;
      the same after the level changes from träning to nivå 2; a drawn
      answer stored, then the kind confirmed as open at nivå 2 → listed
      with `free_start_required`; the same classes at nivå 4 → not
      listed. Nothing stored is changed by confirming a kind or
      setting a level.

- [ ] **Step 3, PATCH guards** (`classes.ts` ~148):
  - `{ start_method: 'free_start' }` for a confirmed age class at
    nivå 1–3 → 409 `{ error: 'free_start_forbidden' }`, nothing stored.
    An unconfirmed (name-suggested) kind, nivå 4, and an open class → 200.
  - `{ start_method: 'start_time' | 'start_punch' }` for a confirmed open
    class or inskolning at nivå 1–3 → 409
    `{ error: 'free_start_required' }`, nothing stored. The same class at
    nivå 4, träning or no level → 200.
  - Optional `if_start_method` (the value the screen saw): if the stored
    value differs → 409 `{ error: 'start_method_changed', start_method:
    <stored> }`, nothing stored. Without the field the PATCH behaves as
    today. Tests for both, including a repeated undo (second one 409).

- [ ] **Step 4, draw guard** (`lottning.ts` POST ~204): a draw of a class
      stored as `free_start` → 409 `{ error: 'free_start_class' }`; no

      does not read `startMethod` today.

- [ ] **Step 5, defaults:** in `draw/classKind.ts`

  ```ts
  /** The start choice a new class gets (ADR-0018). */
  export function defaultStartMethod(kind: ClassKind | null): StartMethod {
    if (kind === 'oppen' || kind === 'inskolning') return 'free_start';
    return kind === null ? 'start_punch' : 'start_time';
  }
  ```

  Use it in `classes.ts` POST (~209; the kind in the request, else
  `suggestClassKind(name)?.kind ?? null`) and in `courseImport.ts` (~120;
  it already calls `suggestClassKind`). Tests: created "Inskolning" →

  an imported course file. Then a projection test per default for a
  runner with a punch and no start time, a start time and no punch, and

  start time (even with a punch), and any class with neither source.
  `grep -rn "'auto'" apps/edge/src --include=*.ts` must show only reads,
  the schema default, fallbacks for a missing row, and tests. The column
  default stays `auto`.

### Task 3: "Så startar klassen" in Lottning (web)

**Files:** `apps/web/src/lib/screens/LottningView.svelte` (the field ~859,
`saveStartMethod` ~624, `startMethodHelp` ~647), `screens/lottning.ts`
(~203, start-order note by kind), `api/client.ts`, `sv.json` (~864),
`en.json`, `LottningView.test.ts`, `tests/e2e/lottning.spec.ts`,
`tests/e2e/helpers/lottning.ts`, `screen-floors.spec.ts`, `a11y.spec.ts`.

**Behaviour tests (RED first unless noted):**

- A radio group "Så startar klassen" with three answers, in the place of
  the old select (first control after the class select), each with a
  second line:
  - "Lottad starttid" — "Startlista. Tiden räknas från starttiden."
  - "Lottad starttid och startstämpling" — "Startlista som sprider ut
    starten. Tiden räknas från startstämplingen."
  - "Fri start med startstämpling" — "Ingen startlista. Kontroll frågar
    inte efter starttider."
- Choosing an answer saves through the per-class queue
  (`saveClassSetting`, key `start_method`), sending `if_start_method` with
  the value the queue last confirmed, and shows `SavedNote`. A failed
  save puts the stored answer back with "Valet sparades inte. Försök
  igen." A 409 `start_method_changed` reloads the class and says "Valet
  ändrades på en annan skärm. Kontrollera och välj igen."
- A class stored as `auto` has no answer ticked and the line "Inget val
  gjort (äldre tävling). Tiden räknas från löparens starttid om den
  finns, annars från startstämplingen."
- Where the lottning GET says `free_start_banned`, the third answer is
  disabled with "Fri start är inte tillåten i åldersklass på nivå 1–3
  (TR 7.4.2)." A 409 `free_start_forbidden` shows that text, never the
  code. If such a class is stored as `free_start` (the kind was confirmed
  later), the group shows the conflict text and no answer is offered as
  fine until another is chosen.
- Where the lottning GET says `free_start_required` (a new flag next to
  `free_start_banned`; a confirmed open class or inskolning at nivå 1–3),
  the two drawn answers are disabled with "Öppen klass ska ha fri
  starttid på nivå 1–3 (TR 7.4.3)." A 409 `free_start_required` shows
  that text. If such a class is stored with a drawn answer, the group
  shows the conflict text until free start is chosen. At nivå 4 and on a
  training race all three answers are open for every class (test: "Gul"
  at träning takes "Lottad starttid och startstämpling" and can be
  drawn).
- When the race has started, the group has the line "Tävlingen pågår. Ett
  byte räknar om tiderna för klassens löpare."
- Lotta is disabled with a hint when the stored answer is free start
  ("Klassen har fri start. Välj Lottad starttid för att lotta.") **and
  while a start-choice save is pending** (the queue updates the stored
  value only when the save settles). A 409 `free_start_class` from the
  draw shows the same hint text.
- The start-order note from `screens/lottning.ts` follows the stored
  answer, not the class kind: it no longer says every open class is timed
  from the punch.

**Edits:** replace the `<Select>` and `START_METHODS` with a `<fieldset>`
and three radio rows (44 px rows, 24 px radios, as the walk-up consent
row), each `aria-describedby` its second line. Remove the old
`lottning.startMethod.*` keys that lose their consumers (grep first).
Floors and a11y: the "full" state shows the group with a saved note; a
second state shows the banned answer, its hint and the disabled Lotta;
assert each visible before measuring; prove the entry by shrinking one
new text to 12 px once.

**Commit:** `feat(lottning): one start choice with three answers`

**Edits:** the open-class hint becomes "Öppen klass: välj Fri start om
klassen inte ska lottas." Floors and a11y: the Kontroll state shows both
