## Top gaps to fix before the 634-runner replay (in priority order)

1. **Replay injection and the race gate (both sides).**
   - `race_started_at_ms` is NULL when a competition is created (`routes/competitions.ts:126`). Until it is set, every read stays PEND (`reduce.ts:214-219`).
   - `event_time_ms` is always `Date.now()`. Neither the bridge nor `simulate-read` accepts a historical timestamp or competition id, and there is no DB injector.
   - What you need: start the race before replaying (the harness seeds `raceStartedAtMs: 0`) or write `race_started` first, then use a proper injector.
   - `feat/replay` (`be1f2d3`, `b5d6964`) has an anonymised MeOS-day replay tool that is not on `phase-2.1`.
2. **MP rule is too strict (both; designed and locked by `dnfMp.test.ts` test 4).**
   - Any extra punch (a stray control or a double punch) or any out-of-order punch gives MP (`dnfMp.ts:148-149`). Real rules check that the course controls appear *in order as a subsequence* of the punches.
   - Repeated controls (butterflies, spectator controls) break the "each code at most once" assumption.
   - Expect dozens of false MPs out of 634.
3. **Drawn start time is never used for elapsed (both).**
   - The reducer only uses the card's start punch (`dnfMp.ts:69`). With no start punch, elapsed is null, so the runner is OK but gets no place and no Time in the ResultList.
   - Open-start classes do work, through the start punch.
   - What you need: a per-class choice of start-list time vs. punched start, using the drawn time when there is no punch.
4. **Start times are stored in two different bases (both).**
   - Lottning writes local ms since midnight. StartList import writes epoch UTC.
   - Each consumer assumes one or the other:
     - `iofExport.ts:450` uses `toISOString()`.
     - `mopBuilder.ts:164` divides by 100.
     - `ReadoutView.svelte:240` and `LottningView` take `% 86400000`, which gives UTC wall-clock.
     - `KvarISkovenView` uses local time.
   - Fix this before item 3, or the elapsed time will be off by hours.
5. **AM/PM is lost on the live chain (both).**
   - `SiTime` gives 0–43200 and the PM bit is never read. Every run crossing 12:00 computes as about 12 h plus elapsed (`halfDayClockMath.ts:49`, 24 h modulo).
   - This also blocks comparing card times with epoch start times.
   - It does not bite if the replay writes payloads with a correct `half_day`. It does bite on real hardware. SI5 needs half-day inferred from read time.
6. **Class↔course mapping (both). Check against the real CourseData file.**
   - A course has a single `classId` (`courseImport.ts:134`), and `ClassCourseAssignment` is last-wins per course name (`parse.ts:242`). Classes that share a course lose it: the expected list is empty, so any punch gives MP.
   - If the file has zero `<Class>` elements (run `grep -c '<Class>'`), classes are synthesised from course names (`courseImport.ts:64`), and every EntryList row is dropped as `classes_missing` (or a hard error is raised).
   - CourseData forks or variations use only the first control.
7. **Runners and cards silently lost at import (both).**
   - EntryList rows are skipped when the class is unknown, or when the card number duplicates another entry in the competition (`entryImport.ts:96-114`).
   - StartList import matches by SI card only. It never updates `card_number` (rented or changed cards stay unmatched), never creates competitors, and sends name-only matches to manual confirmation.
   - Unknown cards only appear in `pending_unknown_cards` (`reduce.ts:191`). They never get a result.
   - No IOF/Eventor person id is stored, so comparison has to be by name or card.
8. **Voided controls (neither side is correct).** Local: a runner who missed the voided control stays MP. PR: a runner who punched it gets MP. It is per-competitor REST only, with no UI and no course-wide void, and it matches by code rather than position. Replacement controls have no write path.
9. **Hardware decode coverage.** SI8 (2M–3M), SI6 and SI11 are not decoded (`SiCard9.ts:161` and siblings). This only affects the live chain, but SI8 is common.
10. **Result-comparison artefacts.**
    - Ties get different places (`reduce.ts:514-518`, `place++`).
    - MAX overrides MP (`reduce.ts:244-251`).
    - Runners never read stay PEND instead of DNS.
    - The ResultList has no StartTime, FinishTime, splits or Course (`courses: []`).
    - Separately, the edge test suite hangs on `push.test.ts` Test 5, so the gate is red until that test's fake fetch honours the abort signal.
