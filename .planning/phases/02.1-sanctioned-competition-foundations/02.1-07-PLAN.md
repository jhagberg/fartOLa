<objective>
Liveresultat push integration.

Purpose: Pushes live results to liveresultat.orientering.se in MOP XML 2.0 format (Claude's discretion per D-09). The push runs on an async queue that never blocks local results (D-10). The operator triggers a push from the UI or it auto-pushes after each card read.

Output: MOP XML builder, push function, retry queue, trigger route.

**Known limitation (DeepSeek MEDIUM — documented for Phase 2.2):** The push queue is in-memory only. If the edge server crashes or restarts mid-push, pending/retrying pushes are lost. This is acceptable for Phase 2.1 because: (1) the queue recovers on next card read (auto-push re-triggers), (2) the liveresultat server is idempotent (re-pushing the same snapshot is safe), (3) the operator can manually trigger a push via the UI. For Phase 2.2, consider persisting the queue state to SQLite (a single-row table with last_push_at and retry_count) so recovery is automatic without waiting for the next card read.
</objective>
