## Implementation Decisions

### Architecture: multi-workstation

- **D-01:** Two laptops, one edge server. Laptop 1 runs the full edge
  bridge with 1-2 SI readers (multi-serial). Laptop 2 runs Chrome
  pointing to Laptop 1's IP for registration help. No peer-sync.
  Disaster recovery: MeOS is the parallel backup. Full two-laptop
  autonomous operation is a later phase.
- **D-02:** Multi-serial support via repeatable `--serial` flag. One
  `BridgeLifecycle` instance per serial path, all sharing the same
  SQLite + WebSocket broadcast. Position tagging (left/right) so the
  walk-up modal auto-opens on the correct browser window when a card
  beeps on a specific reader.

### Start list (lottning)

- **D-03:** Draw modes for Phase 2.1: **SOFT** (federation standard —
  club-blocking), **Random** (trainings), **Simultaneous** (mass start).
  Other MeOS methods (Clumped, Seeded, Pursuit) deferred.
- **D-04:** SOFT algorithm re-implemented from MeOS source
  (`oEventDraw.cpp:130-209`): group by club → distribute into N bins
  (N = largest club size) → recursive sub-group permutation →
  interleave. Re-authored against the algorithm, not ported.
- **D-05:** Schema additions: `competitors.start_time_ms INTEGER NULL`,
  `classes.first_start_ms INTEGER NULL`,
  `classes.start_interval_sec INTEGER NULL`.
- **D-06:** Vakanta startplatser — empty slots distributed for late
  walk-ups. Standard practice for sanctioned competitions.
- **D-07:** Re-lotta: wipes prior times for that class only, preserves
  manual edits to other classes. Per-row "ändra starttid" for single-
  runner adjustments.

### MAX auto-compute

- **D-08:** `classes.max_time_sec INTEGER NULL`. Reducer: after
  `dnfMp.detectStatus` returns OK/MP, gate on
  `elapsed_time_ms / 1000 > class.max_time_sec` → promote to MAX.
  Manual override wins (`view.manual_status !== null` short-circuits).

### Liveresultat integration

- **D-09:** Format and push protocol TBD — researcher to investigate:
  (a) MeOS push protocol in `onlineresults.cpp` (HTTP POST with
  `competition` + `pwd` fields + XML body, optionally zipped);
  (b) liveresultat client source code; (c) whether IOF XML 3.0 or
  MeOS MOP XML 2.0 is the right format. Known: liveresultat API is
  read-only for consumers; push uses a separate authenticated upload
  endpoint.
- **D-10:** Push failure MUST NEVER block local results (queue + retry
  pattern).

### Eventor sync

- **D-11:** Entries pull is already built (`downloadEventorEntries` in
  `apps/edge/src/eventor/entries.ts`). Phase 2.1 adds:
  results push, start list push, event linkage (plan 02-10),
  SI card dedup (plan 02-09).
- **D-12:** Results push = automated IOF XML 3.0 ResultList upload to
  Eventor REST API. Start list push = IOF XML 3.0 StartList to Eventor.

### MeOS integration

- **D-13:** MIP `classid` fix: query MeOS REST `?get=class` to build
  `classname → classid` cache. Emit `classid="N"` on every MIP
  `<entry>`. Workaround for `restserver.cpp:1372` bug.

### Gap-analysis quick wins

- **D-14:** Cancelled/Återbud: new `RunnerStatus` enum value. Reducer:
  manual-only (never auto-derived). IOF XML 3.0: `<Status>Cancelled</Status>`.
- **D-15:** Replacement controls: `course_replacements` table. Reducer
  accepts alternative code in that position.
- **D-16:** Voided legs: `leg_voided` event. Reducer subtracts
  `min(actual, max_seconds)`. Reversible via `leg_unvoided`. Per-class
  or all-classes.
- **D-17:** Subsecond timing: display format option per event. Already
  ms internally. Sprint uses tenths.

### Admin codes

- **D-18:** Ship plan 02-08 as designed: Swedish O-feature wordlist
  codes (`<word>-<NNN>`), rate-limited `/access` endpoint + signed
  cookie, ADR-0010. Enables mobile helpers to register walk-ups from
  their phones.

### Test infrastructure

- **D-19:** MeOS SQL dump replay harness: import classes + runners +
  card reads from a real MeOS MySQL/SQLite dump, replay card reads
  through fartOLa's bridge, validate results match MeOS's. High-value
  regression test for the full pipeline.

### Claude's Discretion

- Migration numbering and sequencing for the ~4-5 new schema changes

- Kvar-i-skogen UI layout (operator-facing, not public)
- Liveresultat format decision after research

### Folded Todos

- **N+1 query fixes** (3 items, score 0.6 each) — autoBindNewCompetitors,

## Specific Ideas

- **MeOS SQL dump as test fixture**: Jonas can get the 4-klubbs 2026-05-20 MeOS data and potentially more events. Build a replay harness that imports this data and validates fartOLa produces matching results.
- **SOFT draw algorithm**: re-implement from the MeOS source algorithm (not port — re-author against the documented approach). The algorithm is: group by club → distribute club groups into N bins → recursively sub-group → interleave. See `oEventDraw.cpp:130-209`.
- **Position-aware readers**: tag each serial port with a position label (e.g., "left", "right"). The walk-up modal auto-opens on the browser window associated with that reader's position. This makes the 2-operator registration desk flow smooth.
- **Liveresultat**: MeOS pushes via HTTP POST to a URL with `competition` (ID) + `pwd` (password) as form fields, XML body (MOP XML 2.0 or IOF XML 3.0), optionally zipped. The researcher should confirm the upload endpoint and determine optimal format.
