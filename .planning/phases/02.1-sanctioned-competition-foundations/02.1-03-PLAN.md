    **Import route** — add POST /api/competitions/:id/import/startlist to routes/import.ts:
    - Accept multipart XML file upload (same pattern as existing CourseData import)
    - Call importStartList, match entries to local competitors by (siCard) or (eventor_person_id) or (className + name fuzzy)
    - Addresses review concern (GPT+Gemini HIGH — fuzzy match duplicate risk): Return matches in two tiers: { exact: [...], fuzzy: [...], unmatched: [...] }. Exact matches (by siCard or eventor_person_id) are auto-applied in the transaction. Fuzzy matches (name-only) are returned as "pending_confirmation" — the frontend must present them for operator review before they are applied via a separate POST /api/competitions/:id/import/startlist/confirm endpoint. This prevents "Anna Nilsson" matching "Anna-Karin Nilsson" silently.
    - Write start_time_ms only for exact + operator-confirmed fuzzy matches in a transaction
    - Return { exact: N, fuzzy: M, unmatched: K, fuzzyMatches: Array<{ imported, candidate, confidence }> }

    **POST /confirm endpoint idempotency (DeepSeek HIGH fix):**
    The POST /api/competitions/:id/import/startlist/confirm endpoint must be idempotent. Before writing start_time_ms for each confirmed match, check if the competitor's start_time_ms already equals the imported value. If so, skip the write for that competitor and count it as already-applied. Return { applied: N, alreadyApplied: M }. This prevents duplicate writes if the operator accidentally confirms twice or if the network retries the request.

    **IMPORTANT — Plan 12 coordination (DeepSeek HIGH):** The /confirm endpoint is a write route. Plan 12's preHandler gates write routes for non-localhost requests. Ensure this endpoint is listed in Plan 12's protected-route inventory. The route follows the standard write-route pattern (POST with body, modifies competitor rows) and must be accessible to authenticated helpers on the LAN.
